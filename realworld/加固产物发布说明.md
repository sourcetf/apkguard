# 加固产物：RustDesk 1.5.0 / Dhizuku 2.12.0

用 [apkguard](../../README.md) 对两个第三方应用做的**加固重建包**，供研究与验证使用。
打包前已在 Android 16（API 36，x86_64）模拟器上逐个实测：安装、启动、进程存活、
零崩溃、壳无降级日志。

## 产物

| 文件 | 启用的功能项 | 能否在本机之外运行 |
|------|-------------|-------------------|
| `rustdesk-PORTABLE.apk` | 39 项（47 项中未启用 D2/D3/D5 与 B5/B6/B7/B9；C3 的混淆形态内建在守卫库里） | ✅ 任意设备 |
| `dhizuku-PORTABLE.apk` | 同上 | ✅ 任意设备 |
| `rustdesk-ALL-emu.apk` | 42 项（47 项中未启用 B5/B6/B7/B9） | ❌ 见下方说明 |
| `dhizuku-ALL-emu.apk` | 42 项（同上） | ❌ 见下方说明 |

两个变体都是同一套加固流程，区别只在三个「运行环境检测/绑定」类功能项：

- **D2 Root 检测**、**D3 模拟器检测**：命中即终止进程。加固时测试用的模拟器本身就
  有 root（`/system/xbin/su` 存在）且满是模拟器特征（`model=sdk_gphone64_x86_64`、
  `hardware=ranchu`），所以 `-ALL` 版本在这类环境里**启动即退**——这是它们生效的
  表现，不是崩溃（实测退出时没有任何异常堆栈）。
- **D5 设备绑定**：绑定的是打包那台模拟器的 ANDROID_ID。换设备后校验不通过，同样
  终止进程。因此 `-ALL` 版本**实际上只能在打包用的那台模拟器上跑**。

**要装到自己的设备上用，请选 `-PORTABLE`。**

还有 13 项与检测无关的能力同样包含在 PORTABLE 里：A16~A20 欺骗类手法（假核心文件、
假内层 APK、假权限元数据、字符串池垃圾、花指令）、C7 原生库伪装、A5/A11 资源混淆、
B8 载荷容器化、A15 巨型 Manifest 填充等。

## 2026-10-04 这一版新增的手法

对照 `sample.apk`（一个真实加固样本）逆向出的手法做了 18 项对齐，与上一版的差异：
- **A15 巨型 Manifest 填充**：填充不再是「一段写死的未知 chunk + 全零」，而是
  **藏进合法字符串池内部的一条巨串** + 两个**类型随机**的假 chunk（样本 369 MB 的
  Manifest 里 85.4% 就是这样一条 1.58 亿字符的巨串）。填充因此不再有固定指纹，
  也不能靠「剥离未知 chunk」去掉。
- **A7（新实现）**：反射成员名强制加密 —— `getMethod/getDeclaredMethod/getField/
  getDeclaredField` 用到的名字，无论多短都交给 A2 加密（短名此前会低于最短长度门槛而留在明文）。
- **A10/A18/A14/A8**：垃圾条目与诱饵元数据成族（176 B 共用载荷、纯空格文件、
  `kotlin/` 伪装、4 位 hex 近重名、构建水印 `cfg_mark_<时间戳>_…`、同名不同值四组、
  三段时间戳），诱饵组件放主题化随机包并去掉产品名。
- **arsc 资源条目名随机化**（13% 带 `vx_<type>_` 前缀），并保证「DEX 里按名查表的
  字面量」对应的资源名**不改名**（含从原始输入 APK 采集，避免被 A1/A2 提前抹掉）。
- **A1 对 R 类的处理**：`R`/`R$Type` 类与字段一起改名（对齐样本），`static_values`
  里的资源 ID 保持不变。
- **ZIP / 签名**：所有 deflate 条目带数据描述符；v2 加防剥离属性（`0xBEEFF00D`）；
  签名块 4096 对齐（数据区补零 + verity padding）。
- **签名证书**：改用随机生成的发布身份（不再是 `O=apkguard` 这种工具指纹）。

同一时间，工具的功能项补齐到 **47/47**（全部实现、全部可按需开启）。与本发布相关的：

- **C3 原生库混淆**（随预编译库常开）：守卫库的 C 源码做了字符串加密 + 6 个关键函数
  的控制流平坦化 + 不透明谓词，三个 ABI 的 `strings` 敏感明文命中从 14 降到 0；
  本发布的两个 APK 都带这版守卫库。
- **B5 函数抽取**（`-extract-methods N`，本发布默认未启用）：方法体抽成 stub、运行时
  由壳加载器在内存里回填。实测 dhizuku 抽 50 个方法后装机启动正常、0 异常。
- **B9 双 APK 投放器**（`-dual-apk`，本发布默认未启用）：产物是宿主，原应用作为加密
  插件；模拟器实测宿主落地插件并拉起系统安装器界面。需要安装权限、受 Android 10+
  后台安装限制，按需开启。
- **B6 VMP / B7 Dex2C**：翻译器与（B7 的）NDK 三 ABI 编译链路已落地，DEX 侧接线
  是明确记录的后续切片，本发布未启用。

## 重要说明（请先读）

## 实测结果（模拟器 API 36 / x86_64）

| 变体 | 安装 | 启动 | 进程存活 | 崩溃 | 壳降级日志 |
|------|------|------|---------|------|-----------|
| `*-PORTABLE.apk` | ✅ | ✅ | 12/12 秒 | 0 | 0 |
| `*-ALL-emu.apk` | ✅ | ✅ | 立即退出（D2/D3 按设计拦停） | 0 | 0 |

其它已验证的行为（同一套产物）：

- 壳把加密载荷解密到私有目录（RustDesk 19 份 / Dhizuku 11 份 DEX），Manifest 指向壳
  `Application`，`ClassLoader` 接管成功；
- Termux 同类产物里在终端真实执行命令成功（业务 DEX 与 C2 解密的原生库都可用）；
- 篡改已安装守卫库的 `.text` 后，事件日志出现 `am_proc_died`（C6 完整性自校验 /
  D4 运行期复检确实在生效）。

## 复现

```bash
# 需要 WSL + Android SDK/NDK + JDK（Windows 侧没有 JDK）
bash scripts/wsl-emu-portable.sh rustdesk dhizuku   # 生成 PORTABLE
bash scripts/wsl-emu-all.sh                         # 生成 ALL / NODETECT
bash scripts/wsl-emu-portabletest.sh                # 装机验证
```

产物断言（逐个功能项核对产物里真的留下了痕迹）：

```bash
python scripts/verify-products.py realworld/emu-out/rustdesk-PORTABLE.apk "<功能项列表>" --channel emu
```
